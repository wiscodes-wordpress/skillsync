# ss-roadmap

**Initiative — wayfind → lenses → publish → app map.** Entry for major / foggy features (not the daily Story spine). See [`ss-flow.md`](../harness/ss-flow.md).

One entry point for a **major feature** (e.g. an AI chatbot): optional wayfinder (local HTML, **no Jira**), draft the roadmap **without** creating tracker issues, lock the plan lenses that matter (architecture / UX / security), **then** publish epics and v1 stories, regenerate `.harness/app-map.html`, and hand off to `/ss-plan`. Judgment stays in the skills; pack structure and app map are scripted.

## Cadence (do not invert)

```text
0. wayfind (optional) — local HTML until route clear; skip if already clear; no Jira
1. draft roadmap (markdown only)
2. lens gates + feature pack
3. lock required lens HTML
4. publish Jira epics (+ v1 stories)
5. render-app-map.cjs — regenerate grand plan mind map
6. /ss-plan per story
```

**Why publish last:** lens plans change stage shape, journeys, and trust decisions. Creating epics/stories before those lock forces rewrite in Jira or ships stale implementation specs. `#phase` / finish-line get real keys on the publish pass (rewrite the same HTML).

**Read vs create:** early steps may **read** existing Jira (related epics, portfolio) for context. They must **not** create or transition issues until the publish step.

In **Agent** mode:

0. **Wayfind (optional)** — if the destination is foggy, follow [`wayfinder`](../skills/engineering/wayfinder/SKILL.md): chart or work `.harness/wayfinder/<slug>/map.html` + tickets. **Never create Jira issues.** Skip when the user says the route is already clear, or an initiative spec / locked lenses already exist. After charting, optionally:

   ```bash
   node .cursor/vendor/skillsync/tools/render-app-map.cjs . --title "<product>"
   ```

1. **Draft roadmap (no Jira create)** — if a wayfinder map exists for this slug, read Destination + Decisions so far first. Follow [`major-feature-roadmap`](../skills/engineering/major-feature-roadmap/SKILL.md) through **synthesize → approval Q&A → write initiative spec markdown** only. Stop before “Create Jira epics / v1 stories”. Optionally **search/read** existing epics for context. Resolve or defer all `Blocks: v1` ambiguities. Note the slug from the spec path (`.harness/initiatives/<slug>/initiative.md`).

2. **Lens gates** — from the draft, decide which lenses this initiative requires. Recommend, then confirm with the user:

   | Roadmap signal | Required lens |
   |----------------|---------------|
   | Structure undecided / ADR candidates / `Blocks: initiative` ambiguity | `arch` |
   | UI-heavy v1 capability or UX constraints on features | `ux` |
   | Cross-cutting security capability, new trust surface, PII/egress ambiguity | `security` |
   | None of the above | Skip pack — go to publish (step 4) with epic/story titles from the draft |

3. **Build the pack** (when ≥1 lens required). Create the initiative first in the Orchestrator Paseo plugin (`server/harness-layout.ts` in github.com/denmercs/Orchestrator): **Harness plan → Initiatives → New initiative**, using the slug from step 1. That writes `initiative.md` and the first `epics/E1-<name>/`. If the draft spec from step 1 already exists, the plugin keeps it. Then add the lens hub:

   ```bash
   node .cursor/vendor/skillsync/tools/init-feature-pack.cjs . \
     --slug <slug> --lenses arch,ux,security
   ```

   Omit `--epics` until publish (or pass draft titles only as comments in the hub). Writes `.harness/initiatives/<slug>/` (`initiative.md`, `index.html` hub, empty `assets/`). Lens HTML stays missing until their commands run.

4. **Run required lens commands in order** — `/ss-arch-plan` → `/ss-ui-ux-plan` → `/ss-security-plan`, each writing **into the pack** (`architecture-plan.md` / `ux-plan.md` / `security-posture.md`, then `render-plan-html.cjs`) instead of freehand HTML, and validating with `validate-plan-html.cjs --file`. Stages / journeys / hardening may use **draft** titles until keys exist; `## phase` can say “keys pending publish”. After each lens lands, rewrite the hub lens row (`missing → draft → locked`). After lenses lock:

   ```bash
   node .cursor/vendor/skillsync/tools/render-app-map.cjs . --title "<product>"
   ```

5. **Publish to Jira** — now create capability **epics** (overview from the initiative spec + locked lens decisions), then v1 **stories** (implementation specs informed by journeys / stages / trust decisions). Write keys into the hub `#keys` table and into each lens file (`data-epic` / `data-story`, finish-line). Re-run:

   ```bash
   node .cursor/vendor/skillsync/tools/validate-feature-pack.cjs . --slug <slug>
   node .cursor/vendor/skillsync/tools/render-app-map.cjs . --title "<product>"
   ```

   Required lenses must exist; every `data-epic` in a lens file must be listed in the hub. App map is regenerated by the script only — do not freehand mind-map JSON ([`app-map`](../skills/engineering/app-map/SKILL.md)).

6. **Handoff** — `/ss-plan` for the first v1 story; point `.harness/state.md` at the pack (`Pack: .harness/initiatives/<slug>/index.html`). Journeys, stages, and trust decisions in the pack seed Behavior & Test Contracts.

**Skip lenses honestly** — a pure API capability with agreed seams may need `security` only, or no pack at all. Do not draft three HTML files for ceremony.

**One-pass roadmap (no lenses):** when step 2 gates require no lens, publish straight from the approved draft (step 5) — that is the whole flow; there is no separate roadmap command.

**Local epics (no Jira):** add each epic with **New phase** in the Orchestrator panel, not by hand, so ids and folders stay `epics/E<n>-<name>/` in every repo. Then write its stories into `stories/`.

**Pack layout:** living plans live under `.harness/initiatives/<slug>/` (`architecture-plan.md` / `ux-plan.md` / `security-posture.md` beside `initiative.md`; HTML derived). Prefer the pack for that train; do not spawn flat `.harness/ux-<slug>.html`. Legacy root `.harness/*.md` is only for simple single-plan repos. Grand plan: `.harness/app-map.html`.

Available as `/ss-roadmap` when linked into **`.cursor/commands/`** (`docs/consumer-setup.md`).
